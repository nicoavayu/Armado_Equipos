## Causa y fix

`r42/outage.mjs` construía `new Worker(new URL('./outage-worker.mjs', import.meta.url), ...)` sin `execArgv`.
Node hereda los argumentos del padre por defecto; `--input-type` es para eval/stdin y no para ejecución desde archivo.
Referencia: https://nodejs.org/api/worker_threads.html#new-workerfilename-options

Reproducción runtime Node v25.2.1: padre `["--input-type=module"]`, worker desde archivo sin override → `ERR_INPUT_TYPE_NOT_ALLOWED`, comprobado como resultado esperado. El control usa un worker mínimo sin Docker ni red.

Fix funcional únicamente en `r42/outage.mjs`: `execArgv: workerExecArgv().execArgv`.
El helper elimina `--input-type=...` o el par `--input-type`, valor; conserva los demás argumentos y su orden. No vacía la lista indiscriminadamente. No agrega retries ni altera el harness, gateway, proxy, TTL, sesiones, D1, allowlist, aislamiento o contratos.

|---|---|---|---|---|
| Normal | `[]` | `[]` | `[]` | Worker ejecutó harness; test falló luego por exit |
| Module | `["--input-type=module"]` | `[]` | `["--input-type=module"]` | Filtro probado; harness de este caso NO ejecutado |
| Separado + legítimo | `["--input-type","module","--trace-warnings"]` | `["--trace-warnings"]` | `["--input-type","module"]` | Worker mínimo confirmó `process.execArgv=["--trace-warnings"]` |

## Resolución del STOP — contrato del `exit` y validación targeted (2026-09-20T22:43–22:49Z)

### Qué es `exit`

`runOutageHarness` devuelve `{...report, bundleSHA256, edgeImage, exit: run.status, mode}`: `exit` es el status de
`docker run … edge-runtime start --main-service outage.eszip`, grabado como dato de evidencia. Ningún caller lo consume:
`matrix.mjs:339` afirma `outage.pass` y tests nombrados; `transport-probe.mjs` usa `pass`/`tests`. El contrato de éxito es
la línea `R42_OUTAGE_RESULT` (su ausencia es `Stop OUTAGE_NO_RESULT`) con `report.pass === true`.

Por qué vale 1 siempre (verificado re-ejecutando sólo el paso `start` sobre el eszip residual `be45c9fb…`, offline, sin secreto):
`outage-harness/index.ts:143` llama `Deno.exit(report.pass ? 0 : 1)` **después** de imprimir el resultado; dentro del isolate
del edge-runtime v1.74.2 `Deno.exit` no existe → `TypeError: Deno.exit is not a function` → `main worker has been destroyed`
→ status 1 incondicional. El harness ya había ejecutado los 29 tests y emitido `pass: true`. Evidencia histórica coherente:
5/5 corridas con `exit: 1`, 4 PASS (28/28 ×3, 29/29 ×1) y 1 FAIL (25/28) → `exit` no discrimina el veredicto.

Conclusión: `assert.equal(r.exit,0)` era una aserción inválida introducida por el test. Se eliminó **sólo** esa aserción
(`worker-invocation.test.mjs` `a956b19f…` → `b991c67d…`). `outage.mjs`, `outage-worker.mjs`, el harness, gateway, proxy,
TTL, sesiones, D1, allowlist, contratos y aislamiento: sin cambios. `pass=true` + 29/29 es el criterio suficiente; `exit!=0`
no representa un fallo real. (Observación, no corregida: `Deno.exit` en el harness nunca funcionó como salida limpia; cambiarlo
alteraría el `bundleSHA256` certificado, fuera de alcance.)
