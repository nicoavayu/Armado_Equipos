# MP-A5 — frontend hybrid commerce (local mock only): decisions, open risks and follow-ups

Scope of MP-A5: the existing Plan / Comprar Premium / PurchaseStatus UI now runs in the hybrid
(staging-v1) composition through the injected service → transport → MP-A4 gateway, behind a TEST
overlay that only a local lab can turn on. Legacy-local keeps its adapter. No migration, MP-A3, MP-A4
gateway, allowlist (43 + 2), Core auth, `/exchange`, token, provider, webhook, legacy payment service,
Vercel or `.env.production*` change. No real Mercado Pago, no remote target, nothing pushed.

## Decisions taken inside the brief

| Topic | Decision |
|---|---|
| Feature model | `entitlements`, `plan`, `billing` stay separate and OFF in the static staging-v1 map. `stagingV1BillingTestOverlay` turns exactly those three on. A fourth key, `plan_legacy_routes` (OFF in hybrid, ON in legacy), gates the legacy Plan redirects and the tournament-scoped purchase routes, so the overlay never re-opens them. |
| Fail-closed billing | `resolveTorneosBillingMode` (foundation/config.js) returns `test` only for `REACT_APP_TORNEOS_BILLING_MODE=test` + hybrid + loopback gateway + loopback Core + app served from loopback + `REACT_APP_DEPLOY_ENV` development/local + `NODE_ENV` ≠ production + `REACT_APP_TORNEOS_PRODUCTION_ENABLED` ≠ true + no Production ref in any target. Everything else is `off` with a reason. The prebuild refuses any build that sets the variable. |
| Billing off ⇒ no commerce request | The composition strips every commerce alias from the service it hands to the providers (`withoutCommerce`) and provides `disabledCommerce`. The competition context and the members page duck-type `loadSeasonEntitlements`; without this an injected service could still read entitlements (RED case). |
| Transport | `commerce(path, body, {timeoutMs})` accepts only `/commerce/v1/season-checkout` and a plain object, and reuses `send()`: same bearer, `credentials: omit`, `cache: no-store`, `redirect: error`, one 401 renewal + repeat (same body, same key), no retry on 403/409/502/503/timeout. `send()` gained only an optional per-call `timeoutMs` (default unchanged). The checkout default is 20 s (gateway: 4 s DB + 8 s payments). |
| Commerce scope | `foundation/stagingV1CommerceScope.js`: the 2 reads + the fixed path, checked against `commerce-test-rpc-allowlist.json` and `commerce.ts` (`COMMERCE_ROUTE`, `EXPECTED_COMMERCE_RPCS`). The client accepts them only when built with `commerce: true`. |
| Service | `loadSeasonEntitlements` (only `get_effective_tournament_season_entitlements`), `loadPurchase` (`get_tournament_purchase`, purchase/org/season must match or `TORNEOS_PURCHASE_FORBIDDEN`), `createCheckout` (body exactly `{organizationId, seasonId, idempotencyKey}`, answer validated: purchase of that org/season + `preference` null or `MERCADO_PAGO` with a URL). Error copy per gateway code; the code stays on the error. |
| Pages | Plan / PurchaseStatus read commerce from `TorneosCommerceContext` (default = legacy adapter, i.e. exactly the functions they imported before). Prices come from the entitlement projection (`formatPlanPrice`); nothing hardcodes 39.900/49.900. One idempotency key per org+season attempt (ref), reused on retry; a synchronous in-flight lock makes a double click one request. `TORNEOS_SEASON_PREMIUM_SUSPENDED` disables the purchase («Compra no disponible»); `TORNEOS_SEASON_ALREADY_PREMIUM` re-reads the plan. |
| G1 stale purchase | The checkout answer's `purchase` is never used for state; only the validated `preference.checkoutUrl` is. `preference: null` (purchase no longer open) opens the purchase status page, where the server decides. |
| Redirect guard | `domain/checkoutRedirect.js`: HTTPS, host `mercadopago.com(.ar)` or a subdomain, no userinfo, no port, no whitespace/backslash, ≤ 4096 chars — validated before `window.location` is touched. Stricter than the legacy guard (adds userinfo/port), same hosts. |
| Premium authority | In hybrid (`entitlementsAuthority`), PurchaseStatus shows «Premium ya está activo» only when the effective season entitlement read after an approved purchase says PREMIUM; otherwise «Pago aprobado · verificando Premium». The redirect route and MP query params only choose the screen. Legacy keeps its previous presentation. |
| Lab checkout | The app is unchanged for the lab: it validates the real Checkout Pro URL and navigates. The browser journey (Playwright) fulfils that navigation with a local page, pays through the mp-stub, sends the signed webhook and follows the Preference's own `back_urls` (origin rewritten to the app). Every non-loopback request is aborted. |

## Open risks

| # | Risk | Status | Needed before |
|---|------|--------|---------------|
| F1 | **Static import edges.** Plan/PurchaseStatus → `TorneosCommerceContext` → `legacyCommerceAdapter` → legacy service reach the Core singleton in the import graph (like `TorneosWorkspaceContext` already did). The B04 audit fixture was regenerated on purpose and the 5 new edges are frozen in foundation.test.mjs. | Runtime: the hybrid provider always overrides the default; Jest traps the singleton and the legacy commerce functions (0 accesses in 39 cases). | None for MP-A5. |
| F2 | **Rejected attempt keeps the purchase open** (MP-A2.1: `preference_created`, `providerStatus: rejected`). The `/fallo` back URL therefore canonicalises to `/pendiente` and PurchaseStatus polls every 4 s while the page is open, with a «último intento no fue aprobado» notice. | Correct by server state; polling stops when the page closes or the purchase becomes final. | Product copy review. |
| F3 | **Approved but not Premium** (activation anomaly / manual refund is not in the purchase projection). The page shows «verificando Premium» and stops polling (final status); the user refreshes. | Fail closed (never claims Premium). | Production: surface anomalies from a server read if product wants it. |
| F4 | **Premium-intent after creating a tournament** (`TournamentWizardPage`, not in the MP-A5 scope) navigates to the tournament-scoped `plan` route, which stays OFF in hybrid → «no disponible». | Untouched on purpose (legacy route). | A follow-up that points it to the season plan. |
| F5 | `OrganizationSettingsNav` (a plan link, outside the listed files) now links «Plan» to the season plan of the route/active season when the legacy redirects are off, and hides it without a season. Legacy unchanged. | Required so the Plan is reachable in hybrid without re-enabling legacy redirects. | None. |
| F6 | **Real Checkout Pro never exercised.** The journey mocks only the Checkout Pro page; everything else is real lab code. | By brief (0 Mercado Pago real). | MP sandbox validation in a later phase. |
| F7 | The browser journey drives the Node gateway (the B04 lab bridge targets 58420). Node/Edge parity of the commerce route is T6 TEST (both gateways, identical verdicts). | Covered by T6. | None. |
| F8 | The app requests a `fonts.googleapis.com` stylesheet (pre-existing, not MP-A5); the journey aborts it. | Inherited. | None for MP-A5. |
| F9 | MP-A4 T6 «U scope» freezes the MP-A4 phase diff against `88cb6ab9`, so it fails on any later phase (here: the MP-A5 frontend files). Its other invariants (migrations 0000/0001/0002 SHA, MP-A3/Core/allowlists/gateway frozen) were verified separately against `02779321`: unchanged. | Expected, by design of the MP-A4 suite. | None. |
| F10 | `test:ci` stops at `psql-connection-live.test.mjs` (6/6): `embedded-postgres` cannot load `libicudata.77.dylib` from the shared node_modules. Identical on base `02779321` (A/B). The rest of the chain was run step by step: all green. | Environmental, inherited. | A node_modules with the complete embedded-postgres binary. |
