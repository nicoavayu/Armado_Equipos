P2 — el rechazo dominante de una competencia Finalizada dice "permisos"
--------------------------------------------------------------------------
Con la competencia Finalizada, todo camino de cliente hacia una escritura queda
cortado ANTES del trigger `protect_tournament_completed_competition`, por la
capability o por RLS:

  reschedule_tournament_match -> 403 TORNEOS_RESOURCE_FORBIDDEN
  save_match_squad            -> 403 TORNEOS_MATCH_FORBIDDEN

O sea que el guard read-only es defensa en profundidad y casi nunca es el que
contesta. El copy de `TORNEOS_RESOURCE_FORBIDDEN` dice "No tenés permisos para
hacer esto en esta organización", que para el propietario de una competencia
finalizada es engañoso: no es un problema de permisos, es que la competencia
está cerrada.

No se corrigió porque tocar eso significa meterse con los guards de capability,
que está explícitamente fuera de alcance.

Atenuante real: por interfaz el propietario nunca llega a ese camino. La UI de
una competencia Finalizada no ofrece acciones mutables —el editor de acta se
renderiza sin ningún botón de guardado— y muestra el estado y la acción
"Reabrir competencia". El mensaje engañoso sólo aparece si un cliente llama la
RPC directamente.
